# TG-041 — Prevent camera uploads from overwriting earlier captures

**Type:** Bug
**Priority:** High
**Component:** backend

**Goal**
Make each ESP32-CAM upload produce a unique storage key so multiple captures from the same device on the same day are preserved.

---

## Current Behavior
`backend/src/routes/camera.ts:70-79` builds one path per device/day:

```ts
const dateSegment = capturedAt.slice(0, 10);
const safeId = sanitize(deviceId);
const blobPath = `camera/${safeId}/${dateSegment}.jpg`;
await writeFile(join(UPLOADS_DIR, `${safeId}_${dateSegment}.jpg`), body);
```

A second upload from the same device on the same day overwrites the first one in mock/local storage and returns the same blob path.

## Expected Behavior
Every upload should have a unique path while keeping a clean date-based hierarchy.

## Scope
- Generate unique camera blob paths and mock filenames.
- Preserve device/date grouping for browsing/debugging.
- Keep the existing `/api/camera/upload` contract.

## Out of Scope
- Moving camera storage to Azure Blob Storage.
- Adding image analysis.
- Changing ESP32-CAM firmware upload behavior unless a new header is required.

## Files to Modify (suggested)
- `backend/src/routes/camera.ts` — include timestamp, uptime, or UUID in `blobPath` and local filename.
- `backend/src/lib/schemas.ts` — only if response schema needs more metadata.

## Steps (Execution Plan)
1. Create a unique filename component from `capturedAt`, `uptimeMs`, or `crypto.randomUUID()`.
2. Change `blobPath` to a structure like `camera/<deviceId>/<yyyy-mm-dd>/<timestamp-or-uuid>.jpg`.
3. Use the same uniqueness in mock/local `writeFile()` path.
4. Ensure returned `blobPath` and `blobUrl` match the actual saved object.
5. Manually upload twice with the same `x-device-id` and verify both files/paths exist.

## Acceptance Criteria
- Two uploads from the same device on the same day return different `blobPath` values.
- In mock mode, two local files are saved instead of one overwrite.
- Existing response fields (`deviceId`, `uptimeMs`, `sizeBytes`, `contentType`, `blobPath`, `blobUrl`, `analysisStatus`, `capturedAt`) remain available.

## Notes for Agents
- Prefer sortable filenames, e.g. ISO timestamp sanitized for paths.
- Keep `sanitize(deviceId)` in place.
