# TG-045 — Make setup completion save profile, greenhouse, and notifications atomically

**Type:** Improvement
**Priority:** Medium
**Component:** frontend / backend

**Goal**
Avoid partial setup completion by moving the final setup save into one backend-owned operation or otherwise adding rollback/consistency handling.

---

## Current Behavior
`frontend/src/features/setup/wizard/SetupWizard.tsx:155-174` performs multiple independent writes during finish:

1. `updateGreenhouse(greenhousePayload)`
2. `updateNotificationPrefs(notificationPrefsPayload)`
3. `saveUserSettings(user.uid, ...)`

`frontend/src/features/setup/api.ts:108-145` writes directly to Firestore from the browser for user/profile settings. If one call succeeds and a later call fails, the app can end up with greenhouse, notifications, and profile state out of sync.

## Expected Behavior
Setup completion should succeed or fail as one coherent operation from the user's perspective.

## Scope
- Introduce a single setup completion flow with consistent persistence.
- Ensure `setupCompleted` is only set after required greenhouse and preferences data are saved.
- Return a clear error if any required save fails.

## Out of Scope
- Redesigning the setup wizard UI.
- Changing crop default selection logic.
- Adding new setup steps.

## Files to Modify (suggested)
- `backend/src/routes/*` or a new setup route — add a backend endpoint for setup completion.
- `backend/src/lib/schemas.ts` — add a request schema for setup completion if needed.
- `frontend/src/features/setup/wizard/SetupWizard.tsx` — replace multiple direct writes with one API call.
- `frontend/src/features/setup/api.ts` — remove or narrow direct Firestore setup completion writes.

## Steps (Execution Plan)
1. Define a backend request payload that includes greenhouse config, notification prefs, and user setup settings.
2. Validate the full payload on the backend.
3. Save all required records from the backend in a controlled sequence or transaction where supported.
4. Set `setupCompleted: true` only after required saves succeed.
5. Return the saved greenhouse/profile summary to the frontend.
6. Update the wizard to call this one endpoint on Finish.

## Acceptance Criteria
- If notification preferences fail to save, `setupCompleted` is not marked true.
- If greenhouse save fails, user profile settings are not marked as completed.
- The frontend Finish action has one success path and one clear error path.
- Reloading after a failed setup finish does not show a half-completed setup state.

## Notes for Agents
- Firebase/Firestore transaction support may shape the implementation. If true atomic transactions are not possible across all stores, document and enforce compensating consistency checks.
