# TG-029 — Fix invisible page headings and off-palette blue colours across the app shell

**Type:** Bug
**Priority:** High
**Component:** frontend

**Goal**
A visual review of the app shell reveals two categories of major presentation defects. First, five of the seven protected pages render their `<h1>` and subtitle text in `text-slate-900` (#0f172a — near-black) directly on the dark navy content background (`bg-[#0f1729]`), making those headings essentially invisible at runtime. Second, the greenhouse palette (evergreen/sage/moss/soil/sunlight) is violated in three separate places by arbitrary blue values (`#2563eb`, `bg-blue-600`, `sky-500`), fragmenting the visual identity. Both defects are high-impact: the first renders content unreadable; the second breaks brand consistency throughout the authenticated shell.

---

## Current Behavior

### 1 — Invisible headings (contrast ~1:1)

`AppShell.tsx` sets the content area background to `bg-[#0f1729]` (dark navy). The following pages override the inherited `text-slate-200` with explicit `text-slate-900` (#0f172a) on their page-level headings and subtitles, which sit **outside any Card** and therefore directly on the dark background:

| File | Line(s) | Classes |
|---|---|---|
| `frontend/src/features/telemetry/SensorDataPage.tsx` | 328–330 | `text-slate-900`, `text-slate-500` |
| `frontend/src/features/alerts/AlertsPage.tsx` | 135–138 | `text-slate-900`, `text-slate-500` |
| `frontend/src/features/timelapse/TimelapsePage.tsx` | 261–264 | `text-slate-900`, `text-slate-500` |
| `frontend/src/features/settings/SettingsPage.tsx` | 109–112 | `text-slate-900`, `text-slate-500` |
| `frontend/src/features/notifications/NotificationsPage.tsx` | 266–270 | `text-slate-900`, `text-slate-500` |

`DashboardPage` and `AssistantPage` are **not** affected — they already use `text-slate-100`.

### 2 — Off-palette blue in the Brand badge (dark variant)

`frontend/src/shared/ui/Brand.tsx` lines 27–28:
```tsx
const badgeBackground =
  variant === 'dark'
    ? 'linear-gradient(135deg, #2563eb 0%, #38bdf8 100%)'   // blue — NOT in palette
    : `linear-gradient(135deg, ${palette.evergreen} 0%, ${alpha(palette.moss, 0.9)} 100%)`
```
The sidebar (which always uses `variant="dark"`) renders a bright blue-to-sky `TG` badge, contradicting every other element on the page.

`frontend/src/shared/ui/SidebarNav.tsx` line 187 also uses off-palette `ring-sky-400/30` on the user avatar ring.

### 3 — Off-palette blue on the Dashboard time-window toggle

`frontend/src/features/dashboard/DashboardPage.tsx` line 177:
```tsx
isActive
  ? 'z-10 bg-blue-600 rounded-xl border text-slate-900 shadow-[…emerald…] ring-1 ring-emerald-300'
  : …
```
The active state uses `bg-blue-600` (#2563eb). The shadow and ring already reference emerald/green correctly; only the fill is wrong.

### 4 — Off-palette blue in the Assistant send button

`frontend/src/features/assistant/AssistantPage.tsx` line 489:
```tsx
className="… bg-gradient-to-r from-emerald-500 to-sky-500 …"
```
`sky-500` (#0ea5e9) is not in the greenhouse palette.

## Expected Behavior

- All five affected page `<h1>` headings and their subtitle `<p>` elements are readable on the dark shell background (light text colour).
- The `Brand` dark-variant badge uses the same evergreen-to-moss gradient as the light variant.
- The `SidebarNav` user avatar ring uses an on-palette colour.
- The Dashboard time-window active button fill is an on-palette green.
- The Assistant send button gradient uses only on-palette greens.

## Scope

- Update text colour classes on the five affected page headings and subtitles.
- Update `Brand.tsx` dark-variant `badgeBackground` to use the existing palette gradient.
- Update `SidebarNav.tsx` avatar `ring-*` class.
- Update `DashboardPage.tsx` active window button `bg-blue-600` class.
- Update `AssistantPage.tsx` send button gradient `to-sky-500` class.

## Out of Scope

- Redesigning the colour palette or any other components.
- Changing the light-variant `Brand` badge (already correct).
- Updating any card heading colours — only the bare page-level `<h1>` and `<p>` elements outside cards are affected.

## Steps (Execution Plan)

1. **Page headings (5 files):** Replace `text-slate-900` → `text-slate-100` and `text-slate-500` → `text-slate-400` on each page's top-level heading block. Example for `SensorDataPage.tsx`:
   ```tsx
   // Before
   <h1 className="text-3xl font-semibold text-slate-900 sm:text-4xl">Sensor data</h1>
   <p className="text-sm text-slate-500">…</p>
   // After
   <h1 className="text-3xl font-semibold text-slate-100 sm:text-4xl">Sensor data</h1>
   <p className="text-sm text-slate-400">…</p>
   ```
   Apply the same pattern to `AlertsPage`, `TimelapsePage`, `SettingsPage`, and `NotificationsPage`.

2. **Brand dark-variant badge (`Brand.tsx` line 27):** Replace the blue gradient:
   ```tsx
   // Before
   ? 'linear-gradient(135deg, #2563eb 0%, #38bdf8 100%)'
   // After
   ? `linear-gradient(135deg, ${palette.evergreen} 0%, ${alpha(palette.moss, 0.9)} 100%)`
   ```

3. **SidebarNav avatar ring (`SidebarNav.tsx` line 187):** Replace `ring-sky-400/30` with `ring-emerald-400/30`.

4. **Dashboard time-window button (`DashboardPage.tsx` line 177):** Replace `bg-blue-600` with `bg-[color:var(--color-evergreen)]` (or the hex `#1F6F4A` from `palette.evergreen`).

5. **Assistant send button (`AssistantPage.tsx` line 489):** Replace `to-sky-500` with `to-[#4FA071]` (i.e. `palette.moss`).

6. Build the frontend (`cd frontend && npm run build`) and confirm zero TypeScript errors.

7. Start the dev server and visually verify each of the five page headings is readable on the dark background.

## Acceptance Criteria

- `SensorDataPage`, `AlertsPage`, `TimelapsePage`, `SettingsPage`, and `NotificationsPage` page `<h1>` text is legible (white/light) against the `#0f1729` shell background.
- The sidebar `TG` badge uses the evergreen-to-moss green gradient in all authenticated views.
- The user avatar ring in the sidebar uses `ring-emerald-400/30` (no blue).
- The active time-window button on the Dashboard is green, not blue.
- The Assistant "Send" button gradient contains no `sky-*` or blue colour tokens.
- `npm run build` succeeds with no type errors.
- No other component styling is changed.

## Notes for Agents

- `palette.evergreen` = `#1F6F4A`; `palette.moss` = `#4FA071`. Import them from `frontend/src/theme/palette.ts` if referencing directly.
- The CSS variable `--color-evergreen` is available in `frontend/src/styles/index.css` if preferred over the hex literal.
- `DashboardPage.tsx` `TimeWindowSwitch` is defined as an **inner component** (line 155). Do not extract it — just update the class string in-place.
- `text-slate-400` for subtitles gives approximately 4.5:1 contrast against `#0f1729`, meeting WCAG AA for normal text.
