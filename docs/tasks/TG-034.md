# TG-034 — Redesign dashboard layout for faster situational awareness

**Type:** Enhancement
**Priority:** High
**Component:** frontend

**Goal**
The current dashboard answers the question *"What does my greenhouse data look like?"* — it does not yet answer the more urgent question a grower asks every time they open the app: **"Is everything OK right now?"** This ticket redesigns the dashboard around that primary question using established best practices for real-time monitoring UIs: status-first hierarchy, sensor cards with inline sparklines, context-aware threshold coloring, a critical-alert banner, a unified multi-sensor chart, and a compact last-readings strip that replaces the full raw-data table.

---

## Current dashboard anatomy (problems mapped)

```
┌─────────────────────────────────────────────────────────────┐
│ Greeting card ← A: vanity space; health badge is too subtle │
├─────────────────────────────────────────────────────────────┤
│ [1h][6h][24h]  Area chart ×3  ← B: 240 px of chart before  │
│                                   the user sees a number    │
├──────────────┬──────────────┬──────────────────────────────┤
│ KPI: Temp    │ KPI: Humidity│ KPI: Soil  ← C: good data,   │
│ 20.0 °C      │ 44.5 %       │ 26.7 %        wrong position  │
├──────────────┴──────────────┴──────────────────────────────┤
│ Recent telemetry (25 rows, 4 cols) ← D: hardest-to-scan    │
│                                       format above alerts  │
├─────────────────────────────────────────────────────────────┤
│ AlertPanel  ← E: most actionable content at the bottom     │
└─────────────────────────────────────────────────────────────┘
```

### Problem A — Greeting card dominates the top without conveying urgency
The `Welcome back, basket of fire caretaker` banner occupies the full width and ~90 px of vertical space at the top. The health badge (`1 critical` / `All clear`) is a small inline pill — a user glancing for 200 ms will see the greeting copy, not the alert state. On mobile the banner wraps and pushes all content further down.

### Problem B — Charts are the first content, numbers come second
A 208 px area chart shows *shape* before it shows *value*. For a monitoring dashboard, reading the current value must take priority over seeing its historical shape. Placing three full charts at the top also means the user scrolls before they see a single number.

### Problem C — KPI cards carry useful data but sit in the wrong position
The cards show `current / start / avg / delta` — that is the right data. But they appear *below* the charts, not above. On a 1440 × 900 screen the KPI cards are not visible without scrolling.

### Problem D — Raw telemetry table is above the AlertPanel
A 25-row raw table is the least at-a-glance-friendly element on the page. Placing it before alerts inverts the urgency hierarchy: the grower scrolls past 400 px of timestamps before seeing whether anything needs their action.

### Problem E — AlertPanel renders below all other content
Due to the single-column grid fallback (see TG-032/033 notes), the `AlertPanel` renders at the very bottom of the page. Even when the grid works correctly, alerts sit next to the data table rather than near the top where urgency demands them.

## Best-practice principles this redesign follows

| Principle | Source / rationale |
|---|---|
| **Status-first hierarchy** | Gestalt proximity: group the most time-sensitive information at the top-left of the reading path |
| **Current value is king** | Nielsen Norman Group — monitoring dashboards should expose the current state before trend context |
| **Sparklines, not full charts, for the overview** | Tufte's data-ink ratio: a 60 × 32 px sparkline communicates the same trend shape as a 400 × 200 px chart while freeing space for actionable content |
| **Threshold-aware color** | Traffic-light coding (green / amber / red) applied directly to the metric value and card border means the grower can judge safety at a glance without reading a number |
| **Critical alert banner** | Industry standard (PagerDuty, Grafana, Datadog): unacknowledged critical alerts appear as a full-width dismissible banner above all other content |
| **"Today" interval over rolling 24 h** | Plants follow circadian rhythms; a grower wants to see *today's* curve from midnight, not a rolling window that shifts with time |
| **7-day interval** | Watering schedules and weather effects manifest over days; weekly context is standard for crop monitoring |
| **Unified multi-sensor chart** | One chart with three series (separate Y-axes or normalized view) is easier to correlate than three isolated charts |
| **Threshold bands on charts** | Shaded "safe zone" regions (e.g., optimal temp 18–26 °C) give charts immediate diagnostic value |
| **Compact readings strip instead of raw table** | The last 5 readings as a horizontal timeline (or a 5-row mini-table without pagination) serve the "recent activity" need without the cognitive load of 25 timestamped rows |

## Detailed spec per section

### Section 1 — Critical alert banner

**Location:** Top of `DashboardPage`, above all other content, rendered only when `active.filter(a => a.severity === 'critical').length > 0`.

```tsx
// Renders above the status row when criticals > 0
<div role="alert" className="…rose-900/50 border-rose-500/40 rounded-2xl px-4 py-3 flex items-center justify-between gap-3">
  <div className="flex items-center gap-2">
    {/* warning icon */}
    <span className="font-semibold text-rose-200">
      {criticalCount} critical alert{criticalCount > 1 ? 's' : ''} require your attention
    </span>
    <span className="text-rose-300 text-sm">— {firstCritical.message}</span>
  </div>
  <div className="flex gap-2">
    <Button size="xs" color="failure" onClick={() => handleAck(firstCritical.id)}>Acknowledge</Button>
    <Link to="/alerts"><Button size="xs" color="light">View all</Button></Link>
  </div>
</div>
```

**Behavior:**
- Appears only for `severity === 'critical'`; warn-level alerts stay in Section 5
- Dismissing (Acknowledge) one critical removes the banner only if no other criticals remain
- Animates in with a subtle slide-down on mount (optional, out-of-scope for this ticket)

### Section 2 — Status row (replaces greeting card)

Replace the full `Card` greeting with a compact single-line status row:

```tsx
<div className="flex flex-wrap items-center justify-between gap-3 py-2">
  <div className="flex items-center gap-3">
    {/* plant icon */}
    <div>
      <h1 className="text-lg font-semibold text-slate-100">{greetingByPlant(profile.plantType)}</h1>
      <p className="text-xs text-slate-400">{lastSeenLabel ?? 'Waiting for first reading…'}</p>
    </div>
  </div>
  <HealthPill criticalCount={criticalCount} warnCount={warnCount} />

```

`HealthPill` is the existing badge logic extracted into a standalone component (green/amber/rose). No `Card` wrapper — this row sits directly in the page flow, saving ~70 px of vertical space.

### Section 3 — Sensor cards with inline sparklines

Each of the three sensor cards becomes a **self-contained status unit**. Current `KpiCards` shows only numbers; this version adds:

1. **Status pill** — colored indicator derived from thresholds stored in `profile` (or safe defaults)
2. **Inline sparkline** — a 40 px tall Recharts `LineChart` without axes, showing the last 2 h of readings
3. **Target range label** — a one-line hint (`Target 18–26 °C`) to anchor the sparkline visually

```tsx
// Threshold logic (new utility, profile-aware)
const sensorStatus = (value: number, low: number, high: number): 'ok' | 'warn' | 'critical' => {
  if (value < low * 0.8 || value > high * 1.2) return 'critical';
  if (value < low || value > high)             return 'warn';
  return 'ok';
};

// Status pill
const statusColors = {
  ok:       'bg-emerald-900/50 text-emerald-300',
  warn:     'bg-amber-900/50 text-amber-300',
  critical: 'bg-rose-900/50 text-rose-300',
};
const statusLabels = { ok: 'In range', warn: 'Out of range', critical: 'Critical' };
```

**Card layout:**
```
┌──────────────────────────────────────────┐
│ Temperature (°C)          ● In range     │  ← label + pill
│                                          │
│ 22.4                                     │  ← large current value
│                                          │
│ [_____/‾‾‾\_____]  sparkline (last 2 h) │  ← 40 px LineChart, no axes
│                                          │
│ Target 18–26 °C   Δ +0.3 over window    │  ← hint + delta
└──────────────────────────────────────────┘
```

The three cards remain in a `md:grid-cols-3` row — same grid as now.

### Section 4 — Unified multi-sensor chart

Replace the three separate `ChartCard` components with a single chart panel. The panel has:

- **Time window switcher:** `2 h` | `Today` | `7 d` (replacing `1h / 6h / 24h`)
  - `2h` = rolling 2-hour window — best for real-time monitoring
  - `Today` = from midnight of the current local date to now — natural for plant care
  - `7d` = rolling 7-day window — weekly pattern visibility
- **Series:** Three `Line` series (Temperature, Humidity, Soil moisture) on a single `ComposedChart`
- **Dual Y-axis:** Left axis for temperature (°C), right axis for humidity/soil (%) — prevents scale compression
- **Threshold reference lines:** `ReferenceLine` at the warn/critical boundaries for each sensor, rendered as faint dashed horizontal lines in the corresponding series color
- **Threshold bands:** Optional `ReferenceArea` fills (very low opacity) highlighting the safe zone for temperature
- **Chart height:** 280 px (desktop) / 200 px (mobile)
- **Legend:** Compact inline legend row below the switcher (three colored dots + labels)

```tsx
// New WindowKey values
type WindowKey = '2h' | 'today' | '7d';

// 'today' filter helper
const filterToday = <T extends HasTimestamp>(items: T[]): T[] => {
  const midnight = new Date(); midnight.setHours(0,0,0,0);
  return items.filter(i => new Date(i.timestamp) >= midnight);
};
```

This chart renders in a single `ChartCard` with `title="Environment trends"` and the window switcher as the `footer` prop.

### Section 5 — Alerts + last readings (below fold)

The bottom section keeps the two-column `lg:grid-cols-[3fr_2fr]` structure but swaps the content:

**Left — Active alerts (full `AlertPanel`, unchanged logic)**
- If 0 active: show "All clear" empty state with a subtle checkmark illustration
- If > 0: list up to 5 alerts (raised from current cap of 3) with acknowledge buttons
- "View all" link

**Right — Last 5 readings (replaces full `RecentTelemetry`)**
Remove the 25-row scrollable table. Replace with a **compact reading strip** — the 5 most recent samples, rendered as a mini-table with only 3 data columns (Temp, Humidity, Soil) plus a relative timestamp ("2 min ago"):

```
  2 min ago    22.4 °C    48 %    18.3 %
  7 min ago    22.1 °C    49 %    19.1 %
  12 min ago   22.0 °C    48 %    20.4 %
  17 min ago   21.8 °C    47 %    21.0 %
  22 min ago   21.5 °C    48 %    21.8 %
              [View full history →]
```

"View full history" links to `/sensor-data` which already has the full table with pagination, filters, and CSV export.

This removes the cognitive load of 25 rows and clarifies the page's purpose: the dashboard is a glance, not a data audit tool.

## Time window changes

| Old | New | Rationale |
|---|---|---|
| `1h` | `2h` | 1 h is often too short to see a meaningful curve; 2 h gives context without losing recency |
| `6h` | `Today` (from midnight) | Plants operate on a day cycle; growers think in days, not rolling hours |
| `24h` | `7d` | Weekly context catches slow drifts (watering depletion, seasonal change) that 24 h misses |

The `filterByWindow` utility in `transforms.ts` needs a `today` case alongside the ms-based ones.

## Notes for Agents

- `sortedSamples` and `chartSeries` are already computed in `DashboardPage.tsx` — `SensorCard` can receive a pre-sliced series prop (last 2 h of `chartSeries.temperature`, etc.) rather than recomputing.
- The sparkline should use `<LineChart>` with `isAnimationActive={false}` and no `<XAxis>` or `<YAxis>` — just `<Line>` inside a `<ResponsiveContainer width="100%" height={40}>`. Set `dot={false}` and `strokeWidth={1.5}`.
- Use `height={40}` (fixed px) on the sparkline `ResponsiveContainer` to avoid the 0-height issue documented in TG-032.
- For the `Today` window: compute `new Date()` with `setHours(0,0,0,0)` on the client — no UTC conversion needed since the chart is for the local grower.
- `ReferenceLine` from recharts accepts `y={value}` and `stroke` props — use `strokeDasharray="4 2"` and low opacity for the threshold lines.
- The `AlertBanner` should read directly from `useAlerts().active`, the same context already available on the dashboard.
- Keep the existing `useAlerts()` polling — do not add a second polling effect.
