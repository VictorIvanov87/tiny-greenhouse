# TG-049 — Split the frontend bundle by route and heavy feature areas

**Type:** Improvement
**Priority:** Medium
**Component:** frontend

**Goal**
Reduce initial frontend load cost by code-splitting route pages and heavy libraries instead of shipping the whole app in one large entry bundle.

---

## Current Behavior
The frontend production build succeeds, but reports a large JavaScript chunk of about 1.52 MB before gzip. Route pages and heavier features appear to be bundled into the initial app payload.

## Expected Behavior
The initial route should load only the app shell and active page. Heavy pages/features should be lazy-loaded when the user navigates to them.

## Scope
- Add route-level lazy loading for major frontend pages.
- Defer heavy chart/assistant/camera/settings code until needed.
- Keep the existing visual behavior and routing paths.

## Out of Scope
- Replacing the router.
- Removing existing features.
- Adding a bundle analyzer dependency unless approved.

## Files to Modify (suggested)
- `frontend/src/app/*` — lazy-load route components where routes are declared.
- `frontend/src/features/dashboard/*` — defer chart-heavy dashboard code if needed.
- `frontend/src/features/assistant/*` — defer assistant/markdown-heavy code if present.
- `frontend/src/features/settings/*` and `frontend/src/features/timelapse/*` — lazy-load page-level modules.

## Steps (Execution Plan)
1. Find the route declaration/app shell where page components are imported.
2. Replace eager page imports with `React.lazy()` and `Suspense` at route boundaries.
3. Keep a lightweight loading fallback consistent with the app shell.
4. Build the frontend and compare emitted chunk sizes.
5. Verify direct navigation and in-app navigation still work for all top-level routes.

## Acceptance Criteria
- `npm run build` still passes in `frontend/`.
- Main entry chunk is materially smaller than the current ~1.52 MB warning chunk.
- Dashboard, assistant, settings, telemetry, timelapse, notifications, and setup routes still render correctly when navigated to directly.
- Loading fallbacks are visible only while lazy chunks load and do not break the dark theme.

## Notes for Agents
- Start with route-level splitting before micro-optimizing individual components.
- Do not add new dependencies without approval.
