# TG-046 — Do not chart missing light readings as zero lux

**Type:** Bug
**Priority:** Medium
**Component:** frontend

**Goal**
Prevent the dashboard light chart from showing false darkness when telemetry samples simply lack `lightLux` data.

---

## Current Behavior
`frontend/src/features/dashboard/components/EnvironmentChart.tsx:96-101` buckets metrics for charting. Light uses a zero fallback:

```ts
const light = bucketByMinute(samples, (s) => s.lightLux ?? 0)
```

Temperature, humidity, and soil moisture pass through the sample value directly. Missing light readings become real zero-lux points.

## Expected Behavior
Missing `lightLux` should be treated as missing data, not as a measured value of 0 lux.

## Scope
- Change dashboard chart data preparation for light readings.
- Preserve genuine zero-lux readings if the sensor actually reports `0`.
- Keep chart behavior consistent with other metrics.

## Out of Scope
- Changing telemetry ingestion schema.
- Changing light thresholds.
- Redesigning the chart UI.

## Files to Modify (suggested)
- `frontend/src/features/dashboard/components/EnvironmentChart.tsx` — remove the nullish zero fallback.

## Steps (Execution Plan)
1. Change the light bucket mapper to pass `s.lightLux` directly.
2. Confirm `bucketByMinute()` skips or handles `undefined` consistently with other metrics.
3. Verify samples without `lightLux` do not create a zero-valued chart point.
4. Verify samples with `lightLux: 0` still render as 0 lux.

## Acceptance Criteria
- Missing light readings do not render as zero lux.
- Actual `lightLux: 0` readings still render as zero lux.
- Temperature, humidity, and soil charts are unchanged.

## Notes for Agents
- This is a data correctness issue: false zeroes can make the greenhouse look dark when the sensor was simply absent/stale.
