# TG-027 — Remove unreachable `profileLoading` check in ProtectedRoute

**Type:** Bug
**Priority:** Low
**Component:** frontend

**Goal**
The `ProtectedRoute` component has a dead code block that checks `profileLoading` a second time — after it was already handled in an earlier guard. This unreachable branch makes the component harder to reason about and could mislead future contributors into thinking there's a deliberate two-phase loading pattern.

---

## Current Behavior

In `frontend/src/app/routes.tsx`, the `ProtectedRoute` component (lines 22–56):

```tsx
// Line 27: first guard — catches ALL loading states
if (loading || profileLoading || profile === undefined) {
  return (
    <div className="flex min-h-screen items-center justify-center bg-white">
      <span className="text-sm text-gray-500">Checking session...</span>
    </div>
  )
}

// Line 35: checks user
if (!user) {
  return <Navigate to="/login" replace state={{ from: location }} />
}

// Lines 39–45: UNREACHABLE — profileLoading was already handled on line 27
if (profileLoading) {
  return (
    <div className="flex min-h-screen items-center justify-center bg-white">
      <span className="text-sm text-gray-500">Checking session...</span>
    </div>
  )
}
```

If `profileLoading` is `true`, the function returns on line 27–33 and never reaches line 39. The second check is dead code.

## Expected Behavior

The unreachable block (lines 39–45) is removed. The component has a clear, linear flow: loading → not authenticated → not set up → render shell.

## Scope

- Remove the dead `profileLoading` check (lines 39–45) from `ProtectedRoute`.

## Out of Scope

- Refactoring the loading/auth flow further.
- Adding tests for `ProtectedRoute` (worthy, but separate ticket).

## Files to Modify (suggested)

- `frontend/src/app/routes.tsx` — remove lines 39–45.
