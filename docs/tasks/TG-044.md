# TG-044 — Align notification timing UI with backend notification preferences

**Type:** Improvement
**Priority:** Medium
**Component:** frontend / backend

**Goal**
Remove the mismatch where setup lets users configure immediate alerts, daily digest, digest hour, and quiet hours, but backend notification preferences only persist email, push, and rules.

---

## Current Behavior
`frontend/src/features/setup/wizard/steps/StepAlarms.tsx:280-309` exposes Immediate alerts, Daily digest, and digest hour controls. `frontend/src/features/setup/wizard/steps/StepAlarms.tsx:314-339` exposes Quiet Hours.

`backend/src/lib/schemas.ts:118-122` defines backend `NotificationPrefs` as only:

```ts
email: z.boolean(),
push: z.boolean(),
rules: z.array(AlertRule),
```

The alert service does not apply digest/quiet-hours/immediate behavior, so the setup UI promises behavior the backend does not enforce.

## Expected Behavior
The product should do one of two things:

1. Persist and honor timing preferences in backend notification delivery, or
2. Clearly mark unsupported timing controls as coming soon / remove them until they are supported.

## Scope
- Decide one implementation path for notification timing behavior.
- Make frontend setup, stored preferences, backend schema, and alert delivery consistent.
- Avoid silently accepting settings that do nothing.

## Out of Scope
- Adding push notification infrastructure.
- Adding email provider setup.
- Rewriting all alert rules.

## Files to Modify (suggested)
- `frontend/src/features/setup/wizard/steps/StepAlarms.tsx` — either adjust UI labels/availability or keep controls if backend support is added.
- `frontend/src/features/setup/wizard/SetupWizard.tsx` — align payload with supported fields.
- `backend/src/lib/schemas.ts` — add timing fields if backend support is implemented.
- `backend/src/services/alerts.ts` — apply quiet hours/digest/immediate rules if backend support is implemented.

## Steps (Execution Plan)
1. Choose whether this release supports notification timing or marks it as coming soon.
2. If supporting it, extend `NotificationPrefs` with `immediate`, `digestDaily`, `digestHour`, and `quietHours`.
3. Update alert delivery logic to suppress/defer non-critical notifications during quiet hours and respect digest settings.
4. If not supporting it, disable or remove the unsupported controls and copy.
5. Verify setup finish does not save no-op preferences without explanation.

## Acceptance Criteria
- Users cannot configure notification timing options that are silently ignored.
- If timing controls remain enabled, backend preferences persist them and alert logic uses them.
- If backend support is deferred, the UI clearly marks timing controls as unavailable/coming soon.

## Notes for Agents
- Keep critical alerts behavior explicit if quiet hours are implemented.
- Do not imply push support exists while the UI marks it coming soon.
