# TG-030 — Address minor frontend UX and code-quality issues found in site review

**Type:** Improvement
**Priority:** Low
**Component:** frontend

**Goal**
A visual review of the tiny-greenhouse frontend surfaced several low-severity issues that individually are cosmetic or low-impact but collectively chip away at polish and maintainability: premature red validation on the login form, a no-op responsive CSS class, an invalid React prop generating console noise, two identically-iconned sidebar links, a native `window.confirm` dialog in the setup wizard, and a missing brand mark on the login page. Addressing them in one pass keeps the codebase clean without warranting separate tickets.

---

## Current Behavior

### 1 — Password helper text appears red before any user interaction

`frontend/src/features/auth/components/AuthCard.tsx` lines 109, 170–175, 286–291:

```tsx
const signInPasswordValid = isPasswordValid(signInForm.password) // false on mount (empty string)
…
<HelperText className={`text-xs ${signInPasswordValid ? 'text-emerald-600' : 'text-red-600'}`}>
  Password must be at least 8 characters.
</HelperText>
```

On first render the password is `""`, so `isPasswordValid` is `false` and the helper immediately renders in `text-red-600`. The same pattern applies to `signUpPasswordValid` on the sign-up card (line 286). Users see a red error state before they have touched the field.

### 2 — Redundant `sm:text-4xl` on the login hero heading

`frontend/src/features/auth/LoginPage.tsx` line 46:
```tsx
className="text-4xl font-semibold leading-tight sm:text-4xl mt-5"
```
Both `text-4xl` and `sm:text-4xl` resolve to the same value. The `sm:` breakpoint is a no-op; the heading does not scale at larger viewports.

### 3 — Invalid `responsive` prop on `<AreaChart>`

`frontend/src/features/dashboard/DashboardPage.tsx` line 133:
```tsx
<AreaChart data={data} responsive>
```
Recharts charts are made responsive by wrapping them in `<ResponsiveContainer>` — which is already done (line 131). The `responsive` prop is not defined in Recharts' `CategoricalChartProps` type and is forwarded to the underlying SVG element, producing a React DOM warning in development: *"React does not recognize the `responsive` prop on a DOM element."*

### 4 — Alerts and Notifications share the same sidebar icon

`frontend/src/shared/ui/SidebarNav.tsx` lines 94–95:
```tsx
{ to: '/alerts',        label: 'Alerts',        icon: BellIcon },
{ to: '/notifications', label: 'Notifications', icon: BellIcon },
```
Both entries render the identical `BellIcon`. The sidebar gives users no visual distinction between these two separate pages.

### 5 — Setup wizard cancel uses `window.confirm`

`frontend/src/features/setup/wizard/SetupWizard.tsx` line 80:
```tsx
const confirmed = window.confirm('Cancel setup and head back to the dashboard? Progress clears.')
```
`window.confirm` is a blocking, un-stylable native browser dialog. It looks out of place in a polished React app and cannot be customised to match the design system.

### 6 — Login page renders no brand identity

`frontend/src/features/auth/LoginPage.tsx` renders only the hero copy and `<AuthCard>`. The `Brand` component (the `TG` logo + "Tiny Greenhouse" name) is never shown. Every other part of the authenticated app displays the brand mark in the sidebar.

---

## Expected Behavior

1. The password helper text is initially neutral (grey) and only turns red after the user has interacted with the field and it remains invalid on blur.
2. The hero `<h1>` on the login page uses a proper two-step responsive size (e.g. `text-3xl sm:text-4xl`).
3. The `responsive` prop is removed from `<AreaChart>`; no React DOM warning is emitted.
4. The Notifications sidebar entry uses a visually distinct icon (e.g. an inbox or mail icon) separate from the Alerts bell.
5. Clicking "Cancel" in the setup wizard opens a Flowbite `Modal` confirmation dialog instead of `window.confirm`.
6. The login page displays the `<Brand>` component (logo + name) above or within the hero area.

---

## Scope

- `AuthCard.tsx`: add a `touched` state to gate the red helper colour.
- `LoginPage.tsx`: fix the redundant `sm:text-4xl` class; add `<Brand />` to the hero.
- `DashboardPage.tsx`: remove the `responsive` prop from `<AreaChart>`.
- `SidebarNav.tsx`: replace `BellIcon` for the Notifications entry with a distinct icon.
- `SetupWizard.tsx`: replace `window.confirm` with a Flowbite `<Modal>` confirm dialog.

## Out of Scope

- Redesigning the login page layout.
- Adding full form validation with libraries (e.g. React Hook Form, Zod) — the touched-flag fix is the minimal improvement.
- Changing the Flowbite component versions or adding new dependencies.

## Files to Modify (suggested)

- `frontend/src/features/auth/components/AuthCard.tsx` — add touched flags for sign-in and sign-up password fields.
- `frontend/src/features/auth/LoginPage.tsx` — fix heading class; add `<Brand />`.
- `frontend/src/features/dashboard/DashboardPage.tsx` — remove `responsive` from `<AreaChart>`.
- `frontend/src/shared/ui/SidebarNav.tsx` — add a new icon for Notifications.
- `frontend/src/features/setup/wizard/SetupWizard.tsx` — replace `window.confirm` with a modal.

## Steps (Execution Plan)

1. **`AuthCard.tsx` — premature red validation**
   Add two boolean state flags and set them on blur:
   ```tsx
   const [signInPasswordTouched, setSignInPasswordTouched] = useState(false)
   const [signUpPasswordTouched, setSignUpPasswordTouched] = useState(false)
   ```
   On the sign-in password `<TextInput>` add `onBlur={() => setSignInPasswordTouched(true)}`.
   On the sign-up password `<TextInput>` add `onBlur={() => setSignUpPasswordTouched(true)}`.
   Update the `HelperText` className conditions:
   ```tsx
   // Sign-in helper
   className={`text-xs ${
     signInPasswordTouched && !signInPasswordValid ? 'text-red-600' : 'text-emerald-600'
   }`}
   // Sign-up helper
   className={`text-xs ${
     signUpPasswordTouched && !signUpPasswordValid ? 'text-red-600' : 'text-emerald-600'
   }`}
   ```
   Reset the touched flags to `false` when `handleFlip` is called.

2. **`LoginPage.tsx` — redundant responsive class**
   Change line 46:
   ```tsx
   // Before
   className="text-4xl font-semibold leading-tight sm:text-4xl mt-5"
   // After
   className="text-3xl font-semibold leading-tight sm:text-4xl mt-5"
   ```

3. **`LoginPage.tsx` — add Brand mark**
   Import `Brand` from `../../shared/ui/Brand` and render it above the hero copy `<div>`:
   ```tsx
   <Brand variant="light" className="mb-4 justify-center" />
   ```
   Adjust `variant` and spacing to suit the dark hero background.

4. **`DashboardPage.tsx` — remove invalid prop**
   Line 133: remove the `responsive` boolean attribute:
   ```tsx
   // Before
   <AreaChart data={data} responsive>
   // After
   <AreaChart data={data}>
   ```

5. **`SidebarNav.tsx` — distinct Notifications icon**
   Add an `InboxIcon` (or similar) SVG component alongside the existing icon definitions, then update the `navBlueprint` entry:
   ```tsx
   { to: '/notifications', label: 'Notifications', icon: InboxIcon },
   ```

6. **`SetupWizard.tsx` — replace `window.confirm`**
   - Add two state values: `const [cancelModalOpen, setCancelModalOpen] = useState(false)`.
   - Replace the `window.confirm` call in `handleCancel` (line 80) with `setCancelModalOpen(true)` (no other logic).
   - Add a `handleConfirmCancel` function that calls `reset()` and `navigate('/dashboard', { replace: true })`.
   - Render a Flowbite `<Modal>` controlled by `cancelModalOpen` with a "Confirm" and "Cancel" button.

7. Run `cd frontend && npm run build` and confirm zero errors.

## Acceptance Criteria

- Signing in: the password helper text is **not** red on initial page load; it turns red only after the password field has been blurred and the value is still shorter than 8 characters.
- The same applies to the sign-up card's password field.
- Flipping between sign-in and sign-up resets the touched state so the red helper disappears.
- The login hero `<h1>` is visibly larger at `sm` breakpoints than at mobile widths.
- The `Brand` logo + name is visible on the login page.
- No `responsive` prop warning appears in the browser DevTools console when viewing the Dashboard.
- The sidebar shows different icons for "Alerts" and "Notifications".
- Clicking "Cancel" in the setup wizard opens a styled modal instead of a native browser dialog.
- `npm run build` succeeds with no type errors.

## Notes for Agents

- For the `Brand` on the login page the hero gradient background is dark (`palette.night`). Use `variant="dark"` so the badge uses the dark-variant style (after TG-029 is merged, that will be the green gradient).
- The `handleFlip` function in `AuthCard.tsx` already calls `setError(null)` — add the touched-flag resets there too.
- For the InboxIcon, a simple SVG is sufficient — no third-party icon library is needed. Match the style of existing icons in `SidebarNav.tsx` (24×24 viewBox, `fill="none"`, `stroke="currentColor"`, `strokeWidth={1.5}`).
- Do not extract `TimeWindowSwitch` or other inner components while removing the `responsive` prop — minimal change only.
