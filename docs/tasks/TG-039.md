# TG-039 — Full frontend UI responsiveness and UX refactor

**Type:** Refactor / Bugfix
**Priority:** Critical
**Component:** frontend

## Goal

Refactor the frontend UI so every route is responsive, scroll-safe, accessible, and consistent with the existing Tiny Greenhouse visual identity. Keep the current colors, icons, fonts, dark-first app shell, Flowbite React component style, and greenhouse brand direction, but remove layout bugs such as hidden controls on mobile/tablet.

## Root cause of the current critical bug

The login page currently combines:

- `h-screen` on the page root
- `overflow-hidden` on the page root
- an inner `h-full` layout
- large fixed vertical padding/gaps
- an auth card with `min-h-[36rem]`

On short mobile and tablet viewports, the hero area plus the auth card is taller than the viewport. Because the root container explicitly hides overflow, the bottom of the login card is clipped and the user cannot scroll to the sign-in/sign-up buttons. This is a blocking authentication bug.

## UX principles for this refactor

1. No route may trap content outside the viewport without a scroll path.
2. Primary actions must remain reachable on mobile, tablet, and desktop.
3. Preserve existing palette, typography, icon style, and brand components.
4. Prefer responsive layout primitives over viewport-height locks.
5. Use Flowbite components according to existing frontend conventions.
6. Keep dark-theme readability and contrast at WCAG AA where practical.
7. Avoid one-off custom colors unless already part of the project palette.
8. Do not introduce new dependencies unless a specific bug cannot be solved with existing tools.

## Scope

### In scope

- Fix login/signup mobile and tablet clipping immediately.
- Audit all top-level routes for `h-screen`, `overflow-hidden`, fixed heights, non-wrapping grids, and clipped controls.
- Normalize page shells, card spacing, form spacing, empty/loading/error states, and responsive breakpoints.
- Refactor repeated layout patterns into shared UI primitives where useful.
- Preserve current colors, fonts, icons, Flowbite usage, and dark theme.
- Add documented responsive QA checks.

### Out of scope

- Changing the brand identity.
- Replacing Flowbite React.
- Replacing Tailwind.
- Redesigning product flows or backend APIs.
- Adding a test runner unless separately approved.

## Phase 1 — Critical auth layout fix

### Task 1.1: Make login page scroll-safe

**Objective:** Ensure sign-in/sign-up buttons are always reachable on mobile/tablet.

**Modify:** `frontend/src/features/auth/LoginPage.tsx`

**Implementation notes:**

- Replace `h-screen overflow-hidden` with `min-h-dvh overflow-y-auto`.
- Replace inner `h-full` constraints with `min-h-dvh` or natural content height.
- Reduce mobile-only vertical padding and gap.
- Keep the hero background, brand, colors, and copy.

**Acceptance criteria:**

- On 360×640, 390×844, 768×1024, and desktop widths, the login form buttons are reachable.
- Page scrolls when content exceeds viewport height.
- Desktop presentation still looks centered and polished.
- No visual identity changes.

### Task 1.2: Confirm flipped sign-up face is also reachable

**Objective:** Ensure both card faces work after the layout fix.

**Modify:** `frontend/src/features/auth/components/AuthCard.tsx` only if needed.

**Acceptance criteria:**

- Sign-in face button is reachable.
- Sign-up face button is reachable after flipping.
- Error messages and helper text do not push controls into an unreachable area.

## Phase 2 — Route-level responsive audit

### Task 2.1: Find layout anti-patterns

**Objective:** Locate hard viewport locks and clipping risks.

**Commands:**

```bash
cd frontend
rg "h-screen|overflow-hidden|min-h-screen|fixed|absolute|grid-cols-|w-\[|min-w-|max-h-|h-\[" src
```

**Acceptance criteria:**

- Every occurrence is classified as safe, needs refactor, or intentionally constrained.
- Findings are documented in this ticket or a follow-up checklist.

### Task 2.2: Normalize protected page layout spacing

**Objective:** Make protected routes use consistent responsive spacing.

**Approach:**

- Keep `AppShell` dark-first structure.
- Standardize page header spacing.
- Use `space-y-*`, responsive grids, and wrapping controls.
- Avoid fixed-width content that breaks below tablet widths.

**Acceptance criteria:**

- Dashboard, Sensor Data, Timelapse, Alerts, Notifications, Settings, Assistant all render without horizontal scrolling at 360px width unless a data table intentionally scrolls inside its own container.

## Phase 3 — Shared UI primitives

### Task 3.1: Add or standardize page primitives

**Objective:** Reduce repeated route-level layout decisions.

**Candidate primitives:**

- `PageHeader`
- `PageSection`
- `ResponsiveCardGrid`
- `ScrollableTableShell`
- `FormActions`
- `EmptyState`
- `InlineError`

**Acceptance criteria:**

- Primitives preserve existing palette and typography.
- No broad visual redesign.
- Repeated page header/card patterns use shared primitives where it reduces code and bugs.

### Task 3.2: Standardize form action behavior

**Objective:** Primary/secondary form actions remain visible and predictable.

**Acceptance criteria:**

- Buttons wrap or stack on small screens.
- Destructive actions use `Button color="red" outline={true}`.
- Save/confirm actions use `Button color="green" outline={true}`.
- Misc actions use `Button color="gray" outline={true}`.

## Phase 4 — Accessibility and interaction polish

### Task 4.1: Keyboard and focus pass

**Objective:** Ensure core flows are keyboard usable.

**Acceptance criteria:**

- Login/sign-up can be completed with keyboard.
- Modal focus behavior follows Flowbite defaults.
- Buttons and links have visible focus states.
- No clickable text without button/link semantics.

### Task 4.2: Loading/error/empty state pass

**Objective:** Every async page has clear loading/error/empty states.

**Acceptance criteria:**

- Dashboard widgets do not collapse awkwardly while loading.
- Tables have empty states.
- Assistant and settings API errors are visible and non-blocking.
