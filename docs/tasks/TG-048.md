# TG-048 — Validate automation settings ranges and cross-field constraints

**Type:** Bug
**Priority:** High
**Component:** frontend / backend

**Goal**
Prevent invalid automation values from being saved, such as impossible percentages or minimum thresholds greater than maximum thresholds.

---

## Current Behavior
`frontend/src/features/settings/AutomationCard.tsx:26-40` passes number input changes directly through `num(e.target.value)` and relies mostly on HTML `min`/`max` attributes:

```ts
onChange={(e) => onChange(num(e.target.value))}
```

`backend/src/lib/schemas.ts:457-483` validates some numeric ranges, but not all sensible constraints. For example, `tempMinC` has no explicit min/max, `tempMaxC` has no explicit range, and the schema does not enforce min <= max relationships.

## Expected Behavior
The frontend should prevent or clearly report invalid automation settings, and the backend should reject invalid payloads regardless of frontend behavior.

## Scope
- Add backend Zod validation for missing ranges and cross-field constraints.
- Add frontend validation or clamping before save.
- Surface clear errors instead of silently accepting invalid values.

## Out of Scope
- Reworking the whole automation UI.
- Changing firmware/device twin protocol beyond rejecting invalid desired settings.
- Adding a new validation library.

## Files to Modify (suggested)
- `backend/src/lib/schemas.ts` — add range and cross-field validation to `ControlSettings`.
- `frontend/src/features/settings/AutomationCard.tsx` — validate/clamp values and disable Save or show errors.
- Any API hook for control settings — ensure backend validation errors are displayed cleanly.

## Steps (Execution Plan)
1. Define sensible allowed ranges for temperature, humidity, soil moisture, fan, pump, and light schedule values.
2. Add Zod `.min()`, `.max()`, and `.superRefine()` checks for min/max pairs.
3. Validate that `tempMinC <= tempMaxC`, `humidityMinPct <= humidityMaxPct`, and `soilMoisturePctMin <= soilMoisturePctMax`.
4. Update frontend save behavior to show validation feedback before sending or display backend validation errors after sending.
5. Manually try invalid values such as humidity 999 and temp min greater than temp max.

## Acceptance Criteria
- Backend rejects invalid percentages above 100 or below 0.
- Backend rejects min thresholds greater than max thresholds.
- Frontend does not show a successful save after backend validation rejects the payload.
- Valid existing/default automation settings still save successfully.

## Notes for Agents
- HTML `min`/`max` attributes are not sufficient validation; users can type or script invalid values.
