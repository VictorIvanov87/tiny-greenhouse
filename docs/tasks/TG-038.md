# Ticket: Hardware mitigations to prevent ESP32 damage from a faulty I2C sensor

## Goal

Add board-level protections so that a single failing sensor (BME280, BH1750, or ADS1115) cannot damage the ESP32 again. The recent firmware changes (TG-038's predecessor work in `hardware/esp32-firmware/src/sensors.cpp`) handle the *software* side — health flags, validation, I2C bus recovery, watchdog, periodic re-init. Those are great at *detecting and degrading gracefully*, but they cannot stop electrical damage that has already started by the time bad data reaches `loop()`.

This ticket covers the **hardware changes** required to make sensor failure non-destructive.

---

## Why this is needed

A previous BME280 unit failed and took the host ESP32 with it. Sensor-induced MCU damage is almost always electrical, not logical:

- VCC↔GND short inside the sensor → excessive current sunk through the ESP32's 3.3 V LDO
- Internal sensor failure pulling SDA/SCL above VCC or below GND → latch-up / ESD damage on GPIO
- Sustained over-current → LDO thermal failure
- Wrong supply voltage backfed through I2C clamp diodes

None of those are detectable in firmware before the damage is done. The firmware already does the most it can do (graceful degradation, periodic re-init, sensor_error telemetry). What's left is hardware.

---

## What to implement

The mitigations below are listed roughly in cost/benefit order. The first one (per-sensor power gating) gives the largest protection per part. Implement at least items 1–3 in any board respin; items 4–5 are nice-to-have.

### 1. Per-sensor high-side power gating (P-MOSFET on VCC)

For each I2C sensor breakout, place a small P-channel MOSFET (e.g. AO3401, DMG2301L) in series with its 3.3 V supply. Drive the gate from a spare ESP32 GPIO via an NPN level shifter or directly through a gate resistor + pull-up.

This lets the firmware **cut power to a sensor** when `tryReinitDisabledSensors()` keeps failing or when a runaway current is suspected. It also enables a clean power-cycle reset on init failure.

Suggested GPIOs (avoid strapping pins): GPIO25 / GPIO26 / GPIO27 are free on the current pinout.

### 2. Series resistors on SDA and SCL

Put a ~100 Ω resistor in series with each I2C line, between the ESP32 and the sensor bus. Limits fault current if a sensor pulls SDA or SCL outside the supply rails. Cheap insurance.

### 3. TVS diodes on SDA / SCL to GND

Add a low-capacitance bidirectional TVS (e.g. SP0503BAHTG or ESDA6V1L) from SDA→GND and SCL→GND. Clamps transients and ESD events that would otherwise reach ESP32 GPIO.

### 4. Separate 3.3 V LDO for sensor rail

Run sensors off a dedicated LDO (e.g. AP2112K-3.3) instead of sharing the ESP32 module's regulator. A sensor short then trips the sensor LDO into thermal limit without dragging the ESP32 supply down.

### 5. Resettable PTC fuse on sensor 3.3 V rail

A small PTC (e.g. 100–200 mA hold) inline with the sensor LDO output. Self-recovers after a transient short and avoids needing to physically replace anything if a sensor briefly misbehaves.

---

## Firmware-side changes that go with this

If item 1 (power gating) is implemented, the firmware should:

1. Add `SENSOR_POWER_PIN_*` constants in [hardware/esp32-firmware/src/config.h](hardware/esp32-firmware/src/config.h).
2. In `setup()`, drive each sensor power pin HIGH (or LOW depending on P-MOSFET polarity) before `Wire.begin()`.
3. Extend `tryReinitDisabledSensors()` to power-cycle a sensor before re-init: drive the power pin OFF for ~100 ms, then ON, then re-run `initBme280()` / `initBh1750()` / `initAds1115()`.
4. On a *third* consecutive `tryReinitDisabledSensors()` failure, leave the sensor's power off until reboot. Report the persistent failure in the next status message.

Items 2–5 require no firmware changes.

---

## Acceptance criteria

This ticket is done when:

1. The sensor breakouts on the next board revision have per-sensor P-MOSFET power gating (item 1).
2. Series resistors are present on SDA/SCL (item 2).
3. TVS diodes are present on SDA/SCL to GND (item 3).
4. Firmware exposes a way to power-cycle each sensor and uses it from `tryReinitDisabledSensors()`.
5. Bench test: deliberately short VCC↔GND on a sensor pad → ESP32 stays alive, sensor power is cut, telemetry reports the failure.

Items 4–5 (separate LDO, PTC fuse) can be deferred to a later board spin if board area is tight.

---

## Non-goals

- Replacing the existing breakouts with custom-built sensor boards.
- Moving away from I2C entirely.
- Redesigning the MOSFET driver module.
- OTA firmware updates (separate concern).
