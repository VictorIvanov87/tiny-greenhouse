# TG-043 — Preserve disabled setup alarm rules instead of dropping them

**Type:** Bug
**Priority:** Medium
**Component:** frontend

**Goal**
Save alarm rules with their enabled/disabled state so user choices in setup are not lost.

---

## Current Behavior
`frontend/src/features/setup/wizard/SetupWizard.tsx:131-135` filters rules before saving notification preferences:

```ts
const enabledRules = state.alarmRules.filter((r) => r.enabled);
const notificationPrefsPayload: NotificationPrefs = {
  email: state.prefs.notifications.email,
  push: state.prefs.notifications.push,
  rules: enabledRules,
};
```

If the user disables a preconfigured rule during setup, that rule is omitted entirely instead of being saved as disabled.

## Expected Behavior
All configured setup rules should be persisted, and each rule's `enabled` flag should represent the user's choice.

## Scope
- Stop filtering out disabled rules during setup finish.
- Keep the existing `AlertRule.enabled` field as the source of truth.
- Confirm notification preferences can store disabled rules.

## Out of Scope
- Changing alert evaluation behavior.
- Redesigning the StepAlarms UI.
- Adding new notification channels.

## Files to Modify (suggested)
- `frontend/src/features/setup/wizard/SetupWizard.tsx` — save `state.alarmRules` instead of only enabled rules.
- `backend/src/lib/schemas.ts` — verify `NotificationPrefs.rules` accepts disabled rules through `AlertRule.enabled`.

## Steps (Execution Plan)
1. Replace the `enabledRules` payload with the complete alarm rule list.
2. Ensure each rule includes a stable `id`, `metric`, `condition`, `value`, and `enabled` flag.
3. Verify `updateNotificationPrefs()` receives all rules.
4. Manually disable a default rule during setup and finish setup.
5. Reopen notifications/settings and confirm the disabled rule is still present and disabled.

## Acceptance Criteria
- Disabled setup rules are persisted with `enabled: false`.
- Enabled setup rules are persisted with `enabled: true`.
- No rule disappears solely because the user disabled it.

## Notes for Agents
- Alert evaluation should continue to ignore disabled rules; this ticket is about persistence, not firing alerts.
