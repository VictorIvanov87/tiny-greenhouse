# TG-028 — Use `import.meta.url` for mock data path resolution

**Type:** Bug
**Priority:** Medium
**Component:** backend

**Goal**
The `readMock()` helper resolves mock data files relative to `process.cwd()`, which only works when the server is started from the `backend/` directory. Starting from the project root (`node backend/dist/app.js`) or using a process manager that sets a different working directory will break all mock data loading with a silent `ENOENT`. Switching to `import.meta.url` makes the path resolution reliable regardless of where the process is launched.

---

## Current Behavior

In `backend/src/lib/file.ts` (lines 1–10):

```ts
import { readFile } from 'node:fs/promises';
import { resolve } from 'node:path';

const root = resolve(process.cwd(), 'data', 'mock');

export async function readMock<T>(file: string): Promise<T> {
  const fullPath = resolve(root, file);
  const buffer = await readFile(fullPath, 'utf-8');
  return JSON.parse(buffer) as T;
}
```

`process.cwd()` is evaluated once at module load time. If the working directory is not `backend/`, the resolved path `<cwd>/data/mock/` will not point to the actual `data/mock/` directory.

This affects all services that load mock data:
- `backend/src/services/telemetry.ts` — loads `telemetry.json`
- `backend/src/services/greenhouse.ts` — loads `greenhouse.json`
- `backend/src/services/prefs.ts` — loads `notifications.json`
- `backend/src/routes/timelapse.ts` — loads `timelapse.json`

## Expected Behavior

- `readMock()` resolves paths relative to its own file location using `import.meta.url`, making it independent of `process.cwd()`.
- The `data/mock/` directory is located relative to the project structure (`../../data/mock` from `backend/src/lib/`), not the working directory.
- Mock data loads correctly whether the server is started from `backend/`, the project root, or any other directory.

## Scope

- Replace `process.cwd()` with `import.meta.url`-based resolution in `backend/src/lib/file.ts`.

## Out of Scope

- Changing the mock data directory structure.
- Moving mock data into the backend directory.
- Adding fallback paths or search logic.

## Files to Modify (suggested)

- `backend/src/lib/file.ts` — replace the `root` path resolution.

## Steps (Execution Plan)

1. In `backend/src/lib/file.ts`, replace the path resolution:
   ```ts
   import { readFile } from 'node:fs/promises';
   import { resolve, dirname } from 'node:path';
   import { fileURLToPath } from 'node:url';

   const __filename = fileURLToPath(import.meta.url);
   const __dirname = dirname(__filename);
   const root = resolve(__dirname, '..', '..', '..', 'data', 'mock');
   ```
   This navigates from `backend/src/lib/` up three levels to the project root, then into `data/mock/`.
2. Verify: run `cd /tmp && node /path/to/backend/dist/app.js` — mock data should load.
3. Verify: run `cd backend && npm run dev` — behavior is unchanged.

## Acceptance Criteria

- `readMock('telemetry.json')` succeeds when the server is started from any working directory.
- `npm run dev` from `backend/` continues to work as before.
- The `data/mock/` path is derived from the file's location, not `process.cwd()`.
- No changes to any other file.

## Notes for Agents

- The project uses ESM (`"type": "module"` in `backend/package.json`), so `import.meta.url` is available.
- After the build step (`tsc`), the compiled JS will be in `backend/dist/lib/file.js` — the relative path `../../../data/mock` still resolves correctly because `dist/` mirrors `src/` structure and both are inside `backend/`.
- Do not introduce `__dirname` as a global — keep it scoped to this file.
