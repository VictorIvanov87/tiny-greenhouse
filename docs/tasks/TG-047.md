# TG-047 — Fix lightLux recommendation hints using light-hours bounds

**Type:** Bug
**Priority:** Medium
**Component:** frontend

**Goal**
Stop showing misleading recommended ranges for lux-based alert rules when the available crop defaults only contain light-hours bounds.

---

## Current Behavior
`frontend/src/features/notifications/NotificationsPage.tsx:63-77` maps alert metrics to crop safety bounds:

```ts
case 'lightLux':
  return bounds.light_hours ?? null;
```

`lightLux` rules use lux units, but `light_hours` is duration. The UI can therefore show a recommendation range with the wrong meaning/unit.

## Expected Behavior
Lux alert rules should only show lux-based recommendations. If no lux safety bounds exist, the UI should omit the recommendation hint for `lightLux`.

## Scope
- Remove the incorrect `lightLux -> light_hours` mapping.
- Optionally add a future-safe `light_lux` / `lightLux` bounds field if the crop defaults support it.
- Keep temperature and humidity recommendation hints unchanged.

## Out of Scope
- Changing crop default data unless adding a clearly named lux field is already supported.
- Changing alert rule evaluation.
- Redesigning the notifications page.

## Files to Modify (suggested)
- `frontend/src/features/notifications/NotificationsPage.tsx` — fix `getBoundsForMetric()`.
- `frontend/src/features/setup/state.tsx` or shared crop types — only if introducing a lux-specific bounds field.

## Steps (Execution Plan)
1. Remove the `bounds.light_hours` return for `lightLux`.
2. If a lux-specific bounds field exists or is added, map `lightLux` to that field instead.
3. Confirm `metricUnit('lightLux')` remains lux-oriented.
4. Verify a light alert row no longer displays hours as a lux recommendation.

## Acceptance Criteria
- `lightLux` rules do not display `light_hours` as their recommended range.
- Temperature rules still use `temperature_c` bounds.
- Humidity rules still use `humidity_pct` bounds.
- The UI does not show a recommendation hint when no compatible bounds exist.

## Notes for Agents
- Do not rename user-facing `lightLux` alert rules to light-hours; these are different concepts.
