# TG-024 — Harden secrets management and prevent credential leakage

**Type:** Security
**Priority:** Critical
**Component:** backend, frontend, infra

**Goal**
Production credentials (Firebase service account key, Supabase database connection string, OpenAI API key) live in plaintext in `backend/.env` on disk. Although `.gitignore` currently prevents them from being tracked, the protection is fragile: the root-level `.env` pattern relies on git's implicit recursive matching, and a single `git add -f` or `.gitignore` edit could expose everything. The Firebase client config in `frontend/.env.local` is similarly unprotected. This ticket hardens the setup and rotates the compromised keys as a precaution.

---

## Current Behavior

`backend/.env` (on disk, not tracked) contains real secrets in plaintext:

- **Line 8:** Full Firebase service account private key (`-----BEGIN PRIVATE KEY-----\n...`)
- **Line 11:** Supabase PostgreSQL connection string with username and password
- **Line 13:** OpenAI API key (`sk-proj-...`)

`frontend/.env.local` (on disk, not tracked) contains Firebase client credentials:

- **Lines 3–6:** Firebase API key, auth domain, project ID, app ID

The `.gitignore` at the project root has:
```
.env
.env.*
!.env.example
```

This works today because git matches `.env` recursively. However:
1. There are no explicit `backend/.env` or `frontend/.env.local` entries — the protection is implicit.
2. No pre-commit hook prevents accidental `git add -f backend/.env`.
3. No documentation warns contributors about secret handling.
4. The `.env.example` files don't clarify which values are truly secret vs. safe to share.

## Expected Behavior

- All production credentials are rotated (old ones revoked).
- `.gitignore` explicitly lists `backend/.env` and `frontend/.env.local`.
- A pre-commit hook (or git-secrets / husky check) rejects commits containing private key patterns or API key prefixes.
- `.env.example` files clearly mark which variables are secrets.
- `README.md` documents how to obtain and configure secrets locally.

## Scope

- Rotate all three backend secrets (Firebase SA key, Supabase URL, OpenAI key).
- Add explicit `.gitignore` entries for `backend/.env` and `frontend/.env.local`.
- Annotate `.env.example` files with `# SECRET` markers on sensitive variables.
- Add a lightweight pre-commit check (e.g., grep for `-----BEGIN PRIVATE KEY-----`, `sk-proj-`, `postgresql://`) that blocks commits containing credentials.

## Out of Scope

- Adopting a secrets manager (Vault, AWS SSM, Doppler) — future ticket.
- CI/CD secrets injection — separate concern.
- Firebase security rules audit (separate ticket).

## Files to Modify (suggested)

- `.gitignore` — add explicit `backend/.env`, `frontend/.env.local` entries.
- `backend/.env.example` — annotate secret vs. non-secret variables.
- `frontend/.env.example` — annotate which values are safe for client-side use.
- `package.json` (root or backend) — add a `pre-commit` or `lint-staged` check (if husky is adopted), or a simple shell script.
- `README.md` — add a "Secrets & Environment" section.

## Steps (Execution Plan)

1. **Rotate credentials** (manual, outside code):
   - Generate a new Firebase service account key in the Firebase Console and revoke the old one.
   - Reset the Supabase database password and update the connection string.
   - Regenerate the OpenAI API key in the OpenAI dashboard and delete the old one.
2. **Update `.gitignore`** — add explicit lines:
   ```
   backend/.env
   frontend/.env.local
   ```
3. **Annotate `.env.example` files:**
   - Mark each variable with `# SECRET — do not commit` or `# PUBLIC — safe for client-side`.
   - Ensure placeholder values are clearly fake (e.g., `sk-proj-REPLACE_ME`).
4. **Add a pre-commit secret scan** — create a script (`scripts/check-secrets.sh`) that greps staged files for known secret patterns and exits non-zero if found. Wire it into a git pre-commit hook or husky.
5. **Update `README.md`** — add a section explaining how to set up `.env` files from `.env.example`, where to find credentials, and what to never commit.

## Acceptance Criteria

- Old Firebase SA key, Supabase password, and OpenAI key are revoked and no longer functional.
- `git add -f backend/.env && git commit` is blocked by the pre-commit check.
- `backend/.env.example` and `frontend/.env.example` clearly distinguish secrets from public config.
- Running `git log --all -- backend/.env frontend/.env.local` returns no results (confirms they were never tracked — already true, just verify).
- A new contributor can follow `README.md` to set up env files without guessing.

## Notes for Agents

- Do NOT commit real credentials in any file — use placeholder values in `.env.example`.
- The credential rotation steps (1) are manual and must be done by a human with access to Firebase Console, Supabase dashboard, and OpenAI platform.
- Keep the pre-commit script simple; no new npm dependencies unless husky is already in the project.
