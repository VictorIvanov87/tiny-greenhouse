# TG-040 — Fail closed when production auth mode is not configured

**Type:** Security
**Priority:** Critical
**Component:** backend

**Goal**
Prevent protected backend routes from silently accepting mock authentication in production. A missing `AUTH_MODE` should not turn production into demo/x-user-id mode.

---

## Current Behavior
`backend/src/plugins/auth.ts:7` defaults to `mock`:

```ts
const mode = (process.env.AUTH_MODE ?? 'mock').toLowerCase();
```

Then `backend/src/plugins/auth.ts:47-51` uses Firebase auth only when the mode is exactly `firebase`; every other value falls back to `mockAuth()`, which accepts `x-user-id` or uses `demo`.

## Expected Behavior
Production must fail closed unless real Firebase auth is explicitly configured. Local development may still use mock auth, but only intentionally.

## Scope
- Require explicit auth configuration for production/runtime deployments.
- Keep mock auth available for local development.
- Add clear startup/runtime error messaging for invalid or missing `AUTH_MODE`.

## Out of Scope
- Replacing Firebase auth.
- Changing frontend login UX.
- Adding role-based authorization.

## Files to Modify (suggested)
- `backend/src/plugins/auth.ts` — validate `AUTH_MODE` and reject unsafe production fallback.
- `backend/.env.example` or deployment docs — document required production value.

## Steps (Execution Plan)
1. Define allowed auth modes (`mock`, `firebase`).
2. Detect production via `NODE_ENV === 'production'` or the deployment environment convention already used by the backend.
3. If production and `AUTH_MODE` is missing or not `firebase`, throw a startup error.
4. If non-production and `AUTH_MODE` is missing, keep defaulting to `mock`.
5. If `AUTH_MODE` has an unknown value, throw a clear configuration error instead of falling back to mock.

## Acceptance Criteria
- With `NODE_ENV=production` and no `AUTH_MODE`, the backend refuses to start or returns a configuration error before serving protected routes.
- With `NODE_ENV=production AUTH_MODE=mock`, the backend refuses to start.
- With `NODE_ENV=production AUTH_MODE=firebase`, protected routes require a valid bearer token.
- With local development and no `AUTH_MODE`, mock auth still works.

## Notes for Agents
- Treat this as a security issue, not a cleanup task.
- Do not remove mock mode entirely; just prevent accidental production use.
