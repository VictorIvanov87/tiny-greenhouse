# TG-042 — Persist selected growth stage in user setup profile

**Type:** Bug
**Priority:** High
**Component:** frontend

**Goal**
Ensure the growth stage selected during setup is saved consistently in the user profile, not only in the greenhouse payload.

---

## Current Behavior
`frontend/src/features/setup/wizard/SetupWizard.tsx:138-147` includes `growthStage` in the greenhouse payload, but `frontend/src/features/setup/wizard/SetupWizard.tsx:159-174` does not pass that stage into `saveUserSettings()`.

`frontend/src/features/setup/api.ts:108-145` persists crop, variety, language, notifications, light, climate, soil, timelapse, digest hour, and quiet hours, but not `growthStage`.

`frontend/src/features/setup/state.tsx:25-33` defines `SetupProfile` without a `growthStage` field.

## Expected Behavior
After finishing setup, the selected or default growth stage should be available in the stored user settings/profile and in the frontend profile context.

## Scope
- Add `growthStage` to setup profile/settings types.
- Persist it when finishing the setup wizard.
- Load it into any existing setup/profile context that reads the user document.

## Out of Scope
- Building a full growth-stage management UI.
- Changing crop defaults.
- Reworking assistant behavior beyond making the field available.

## Files to Modify (suggested)
- `frontend/src/features/setup/state.tsx` — add `growthStage` to `SetupProfile` and related state/types.
- `frontend/src/features/setup/api.ts` — add `growthStage` to `SettingsPayload` and Firestore writes.
- `frontend/src/features/setup/wizard/SetupWizard.tsx` — pass the selected/default stage into `saveUserSettings()`.

## Steps (Execution Plan)
1. Compute one `growthStage` value in `SetupWizard` and reuse it for both greenhouse and user settings payloads.
2. Extend `SettingsPayload` with `growthStage`.
3. Write `growthStage` to `users/{uid}` and/or `users/{uid}/settings/preferences`, matching the existing profile loading pattern.
4. Extend `SetupProfile` so consumers can access the field.
5. Verify a setup finish writes the same stage to greenhouse and profile data.

## Acceptance Criteria
- Finishing setup with an explicitly selected stage persists that stage in user settings/profile.
- Finishing setup without an explicit stage persists the same default stage used in the greenhouse payload.
- Reloading the app after setup exposes `profile.growthStage` or equivalent profile state.

## Notes for Agents
- Avoid computing the fallback stage twice in separate expressions; that risks drift.
